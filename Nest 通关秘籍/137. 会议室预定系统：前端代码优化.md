## useCallback、useMemo

前面我们代码里加了很多 useMemo 和 useCallback，其实这是没必要的。

我们创建个测试项目：

```
npx create-vite test-memo
```

![](https://r2.297087852.workers.dev/nest通关秘籍/0b41724ad73939a6-2201fd42f2574c179eaacb65b0aeb37etplv-k3u1fbpfcp-jj-mark0000q75.png)

进入项目，安装依赖，然后把开发服务跑起来：

```
npm install

npm run dev
```

![](https://r2.297087852.workers.dev/nest通关秘籍/5b081a10e6f48a6c-d9077bfa37cb459aa06239b21d5614c9tplv-k3u1fbpfcp-jj-mark0000q75.png)

![](https://r2.297087852.workers.dev/nest通关秘籍/a0b23e921f8bc4f0-9ba1fdc214eb46c9bf19a358cb91d514tplv-k3u1fbpfcp-jj-mark0000q75.png)

去掉 main.tsx 里的 index.css 和 StrictMode：

![](https://r2.297087852.workers.dev/nest通关秘籍/61d6551ed1b0ab5f-bd166d5c3ac34111b624b3395cdfc976tplv-k3u1fbpfcp-jj-mark0000q75.png)

然后改下 App.tsx

```javascript
import { useEffect, useState } from 'react'

function Aaa(props: { text: string }) {
  console.log('Aaa render...');

  return <div>{props.text}</div>
}

function App() {
  const [num, setNum] = useState(0);

  useEffect(() => {
    setInterval(() => {
      setNum(num => num + 1);
    }, 1000);
  }, []);

  return <Aaa text="aaa"></Aaa>
}

export default App
```
App 组件里有一个定时器，不断的修改 setState 来触发重新渲染。

这时候 Aaa 会不会重新渲染呢？

![](https://r2.297087852.workers.dev/nest通关秘籍/9b67b597042238f9-a7ff3b02c2a34641966217878ae22ad6tplv-k3u1fbpfcp-jj-mark0000q75.png)

答案是每次都会重新渲染。

很明显这里 Aaa 不需要重新渲染，因为参数没变。

这时候就可以用 memo 来做：

![](https://r2.297087852.workers.dev/nest通关秘籍/13cc99977960e936-764f27b70f2d43229d49c5f6be886ba9tplv-k3u1fbpfcp-jj-mark0000q75.png)

```javascript
import { memo, useEffect, useState } from 'react'

function Aaa(props: { text: string }) {
  console.log('Aaa render...');

  return <div>{props.text}</div>
}

const MemoAaa = memo(Aaa);

function App() {
  const [num, setNum] = useState(0);

  useEffect(() => {
    setInterval(() => {
      setNum(num => num + 1);
    }, 1000);
  }, []);

  return <MemoAaa text="aaa"></MemoAaa>
}

export default App
```

现在 Aaa 就只会渲染一次了：

![](https://r2.297087852.workers.dev/nest通关秘籍/7f035a69b07bfa74-08c4793ad0864d359c8754b3b15916a3tplv-k3u1fbpfcp-jj-mark0000q75.png)

memo 里会对比 props 和上次有没有变化，没变就不会重新渲染。

那如果我加一个函数作为参数呢？

![](https://r2.297087852.workers.dev/nest通关秘籍/bb5ffd44097fa3b4-49644bfbd1c64a32b8cfa225ffe00b44tplv-k3u1fbpfcp-jj-mark0000q75.png)

```javascript
import { memo, useEffect, useState } from 'react'

function Aaa(props: { text: string, callback: Function }) {
  console.log('Aaa render...');

  return <div>{props.text}</div>
}

const MemoAaa = memo(Aaa);

function App() {
  const [num, setNum] = useState(0);

  useEffect(() => {
    setInterval(() => {
      setNum(num => num + 1);
    }, 1000);
  }, []);

  return <MemoAaa text="aaa" callback={() => { console.log('xxx');}}></MemoAaa>
}

export default App
```
这时候每次都会重新渲染：

![](https://r2.297087852.workers.dev/nest通关秘籍/6f044e52213f2d4d-1cc1d8944c144136b831d936ad5de05atplv-k3u1fbpfcp-jj-mark0000q75.png)

因为函数每次都变，也就是参数每次都变，加了 memo 也没用。

这时候用 useCallback 就可以解决这个问题，它只有依赖数组变的时候才会返回新的函数，否则一直返回同一个函数：

![](https://r2.297087852.workers.dev/nest通关秘籍/8cd83499d548668e-f6d47a1a45f745108704f39181f3c8e6tplv-k3u1fbpfcp-jj-mark0000q75.png)

```javascript
import { memo, useCallback, useEffect, useState } from 'react'

function Aaa(props: { text: string, callback: Function }) {
  console.log('Aaa render...');

  return <div>{props.text}</div>
}

const MemoAaa = memo(Aaa);

function App() {
  const [num, setNum] = useState(0);

  useEffect(() => {
    setInterval(() => {
      setNum(num => num + 1);
    }, 1000);
  }, []);

  const callback = useCallback(() => {
    console.log('xxx');
  }, []);

  return <MemoAaa text="aaa" callback={callback}></MemoAaa>
}

export default App
```

现在又只渲染一次了：

![](https://r2.297087852.workers.dev/nest通关秘籍/8ff6b36e43d4ca89-cd4ead614fd1485f800aef33bf00b059tplv-k3u1fbpfcp-jj-mark0000q75.png)

所以说，memo 和 useCallback、useMemo 是配合使用的，我们之前单独用 useCallback 没什么意义。

代码里的 useCallback 可以去掉。

![](https://r2.297087852.workers.dev/nest通关秘籍/4b8895e15bb6c1d1-94716c97a091477d82686288c16d24abtplv-k3u1fbpfcp-jj-mark0000q75.png)

## 总结

这节我们做了一些前端代码优化。

之前只是做了接口返回 401 的时候跳转登录页的逻辑，现在又补充了路由守卫，在 Index 组件里读取 localStorage 的值，如果没有 user_info 就跳转登录页面。

然后分析了 React 里 memo 的作用以及和 useCallback、useMemo 的配合使用，之前我们单独使用并没有什么意义，可以去掉。

这样，前端代码就没有啥明显的问题了，还有细节上的优化大家可以自己去做。
